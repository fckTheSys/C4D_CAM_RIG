# CamRig 2 — постановочная камера

**Текущее решение:** универсальный P3 сохранён как [legacy](../prototypes/cine_camera/LEGACY.md).
Новая рабочая ветвь разработки — [Cine Orbit / Trajectory / Free](../prototypes/cine_variants/README.md),
три сборки общего кода без Movement mode и без чужих параметров движения.
Ниже сохранена документация универсального P3 и общих эффектов.

Решение пользователя: отдельная новая система. Старый CamRig остаётся рабочим
инструментом и референсом движения. CK_CAM предназначен для POV.

## Цель и границы

Одна выходная камера, понятное управление движением, независимое наведение,
воспроизводимость при перемотке и рендере. Новые сцены используют новый риг;
автоматической миграции старых анимаций нет.

Первый этап P1: орбита, наведение, панорама/наклон/крен, нативная оптика.
Это отдельный прототип, не установленный плагин и не готовый релиз.

## Архитектура

Целевая цепочка: Motion → PositionFX → Aim → Frame → RotationFX → Camera.
P2 не создаёт неработающие слои эффектов: Motion → Position Offset → Aim → Frame → Camera.
Orbit Path и Trajectory находятся отдельно под корнем; Motion ссылается на активный
сплайн. Free Controller — отдельный анимируемый Null под корнем.
Orbit Center и Look Target — отдельные доступные контроллеры под корнем рига.

- Motion определяет положение и базовую ориентацию. В P1 используется нативный
  круговой сплайн и Align to Spline без тангенциального вращения.
- Aim — Null с нативным Target. Режим Manual сбрасывает его вращение;
  ручная композиция задаётся через Frame. Режим выбирается для кадра, не анимируется.
- Frame — панорама, наклон, крен относительно Aim, либо осей корня в Manual.
- Camera — единственная RS-камера (или стандартная при отсутствии RS).
  Фокусное расстояние, дистанция фокуса, DOF и экспозиция редактируются нативно.
  Runtime не перезаписывает оптику и её ключи.
- Prepare выполняется на -30, Align на -20, Target на -10.
  Выражение не вызывает EventAdd, SetTime, ExecutePasses и не меняет структуру сцены.

Роли объектов определяются метаданными, параметры — сохранёнными номерами UD,
а не именами. Объекты заново разрешаются при каждом проходе, без хранения ссылок
между Undo. Вычисление P1 не содержит истории: текущие значения читает из UD,
интерполяцией ключей занимается C4D. Встроенный Python Tag переносится со сценой.

## Параметры P1: практический смысл

| Параметр | Что меняет |
| --- | --- |
| Orbit angle | Положение на окружности в градусах. 360 — полный оборот; 720 — два. Отрицательные значения дают обратное направление. Ключи не ограничены одним оборотом. |
| Radius | Расстояние от оси орбиты. Больше — широкий облёт и более далёкая камера; меньше — тесный облёт. При том же изменении угла больший радиус даёт большую линейную скорость. |
| Height above center | Высота относительно центра по локальной Y корня. Больше — камера выше. При наведении на цель это также меняет угол взгляда сверху. |
| Orbit center | Объект, чья мировая позиция задаёт центр. Его вращение не наклоняет орбиту: плоскость определяется вращением корня. Пустая ссылка использует встроенный Orbit Center. |
| Aim mode | Target автоматически смотрит на цель. Manual оставляет ручную ориентацию относительно корня; при отключении цели текущий кадр автоматически не сохраняется. |
| Look target | Объект, на который смотрит камера. Может двигаться независимо от центра орбиты. Пустая ссылка использует встроенный Look Target. |
| Pan / Tilt / Roll | Поправка композиции: горизонтальный поворот, вертикальный наклон и крен горизонта. В Target поправка применяется после наведения. |
| Output camera | Ссылка на единственную камеру. Выбери её для нативных настроек оптики. |
| Status | Диагностика исполнения; при нарушении поддерживаемых условий показывает причину. |

Движение анимируется ключами Orbit angle, Radius и Height. Разгон/торможение
задаются F-Curve угла. Равномерный угол при неизменном радиусе даёт равномерный
круговой ход. Изменение радиуса добавляет самостоятельное движение к центру/от него.

## План реализации

1. **P1 — основание:** текущий прототип; проверить орбиту, наведение, оптику,
   отрицательные/многократные обороты, subframes, прямую/обратную перемотку,
   независимые копии и сохранение/загрузку. Затем ручная проверка удобства облёта.
2. **P2 — способы движения:** Trajectory с прогрессом и Free с отдельным
   анимируемым контроллером. Режимы выбираются для кадра; панель показывает
   актуальные настройки. Переходы между режимами не входят в первую версию.
3. **P3 — характер:** позиционная инерция, дрейф, тряска. Независимые слои,
   отключённый эффект пропускает расчёт; воспроизводимость на subframes.
4. **P4 — постановочные удобства:** дополнительная цель и смешивание,
   независимая цель фокуса, запекание в обычную камеру.
5. **P5 — поставка:** собственная команда создания и упаковка после приёмки.

### P2 — три режима движения, 15.09.2026

Реализованы Orbit / Trajectory / Free в `Movement mode`. Режим выбирается для
кадра и не анимируется. Переключение не сохраняет прежнюю композицию автоматически:
камера принимает положение выбранного источника. Единая цель, оптика и Frame
сохраняются. Встроенные контроллеры заменяются ссылками на объекты того же документа;
пустая ссылка возвращает соответствующий встроенный контроллер.

| Настройка | Практический смысл |
| --- | --- |
| Trajectory spline | Один редактируемый сплайн с минимум двумя различными точками. Можно передать внешний сплайн. Параметрический сплайн сначала нужно сделать редактируемым. |
| Progress | 0% — начало, 100% — конец пути. Ключи Progress задают движение; кривой регулируются разгон и остановка. Значения ограничены диапазоном 0–100%. |
| Free controller | Анимируй обычные координаты и вращение этого Null. При Manual камера повторяет его ориентацию, при Target смотрит на цель. |
| Local offset X/Y/Z | Смещение камеры до наведения. В Orbit/Trajectory — вдоль осей корня; в Free — вдоль осей Free Controller. Например, Y поднимает камеру без изменения сплайна. |

В Trajectory тангенциальное вращение отключено: направление задаётся общей целью
либо вручную через Pan/Tilt/Roll. Кривизну и гладкость маршрута редактируют ручками
нативного Bezier-сплайна. Отдельная аппроксимация/сглаживание не добавлены.
Progress использует нативную параметризацию Align: линейная F-Curve не гарантирует
равномерную скорость на произвольном сплайне. Компенсация по длине пути пока отсутствует.

P2 live PASS в C4D 2026.2: крайние точки пути (допуск 0.01 см), внешний повёрнутый
сплайн, локальные смещения, ключи Progress и Free Controller, произвольная перемотка
с дробными кадрами, ручная правка Progress с ключами, переходы между режимами,
диагностика циклических ссылок. Регрессию P1 и сохранение/загрузку проверяет
`acceptance.py`; новые режимы — `acceptance_modes.py`.
Повторный полный прогон P1+P2: PASS; fixture с тремя режимами —
`tests/artifacts/cine_p1_e29e1e87ace24ae19b80e7929a7e85b4.c4d`.

Параметры снова находятся в одной нативной панели User Data: Main / Orbit /
Trajectory / Free / Look / Camera / Effects — раскрытые группы. Отдельные вкладки
отменены по просьбе пользователя. Режим задаётся в Main → Movement mode.
Неактивный источник не рассчитывается. Требования масштаба 1 и отсутствия frozen
transforms относятся к технической иерархии; Free Controller также требует единичного
мирового масштаба. На исходных объектах с expression-драйверами нужно отдельно
проверять приоритеты; текущая приёмка покрывает обычные координатные ключи.

### P3 — инерция, дрейф и тряска, 15.09.2026

Реализована цепочка Motion → Position Offset → Inertia → Aim → Frame → Motion FX
→ Camera. Inertia меняет только позицию до наведения. Motion FX добавляет
локальное смещение и вращение после композиции; цель не компенсирует эти колебания.
Камера остаётся одна. В сцене два переносимых Python Tag: Prepare (-30) и Inertia
(-15), между нативными Align (-20) и Target (-10).

Переиспользованы C2 noise из CK_CAM и аналитическая пружина из CamRig 1.6.
Применён прежний принцип просмотра незаписанной правки параметра с ключами.
Новый адаптер читает исторические координаты без перемотки документа и хранит
только числовую историю пружины; изменения оптики, цели и FX не сбрасывают её.
Решатель работает на сетке 120 Гц, дробный остаток рассчитывается отдельно.

| Параметр | Меньше / больше и практическое применение |
| --- | --- |
| Inertia Strength | 0 — точное исходное движение и пропуск истории; 1 — полное отставание пружины. Начать с 0.2–0.4. Можно анимировать для плавного ввода эффекта. |
| Response | Выше — камера быстрее догоняет маршрут, отставание меньше. Ниже — более тяжёлая камера, заметное отставание. Не является скоростью движения по маршруту. |
| Damping | Выше — меньше колебаний после остановки; 100 — критическое затухание. Ниже — камера сильнее перелетает конечную позицию и качается. |
| Shake Strength | Сила быстрых колебаний, 0 отключает расчёт. Небольшая сила даёт ощущение ручной камеры; большая сильно меняет композицию. |
| Drift Strength | Сила медленных поправок камеры. Удобна для едва заметного движения в статичном кадре; не связана со скоростью маршрута. |
| Frequency | Темп смены шумового рисунка: больше — быстрее, меньше — медленнее. Это не периодическая синусоида, поэтому «Hz» — масштаб времени шума, не точный счёт качаний. |
| Position | Масштаб смещений по каждой локальной оси в см. Больше — заметнее параллакс. Итог умножается на Strength. |
| Rotation | Масштаб угловых колебаний по каждой оси в градусах. Больше — сильнее поворот кадра и крен горизонта. Итог умножается на Strength. |
| Pattern seed | Другой воспроизводимый рисунок шумов без изменения их силы и темпа. Общий seed; у Shake и Drift независимые последовательности. |

Response, Damping, Frequency и seed выбираются для кадра. Анимировать их пока
нельзя; при добавлении трека вручную Status сообщает ограничение. Для плавного
появления/исчезновения анимируются Strength, Position и Rotation. Ручная смена
Frequency или seed может изменить фазу рисунка на текущем кадре.

Инерция проверена для всех трёх режимов с обычными координатными/UD ключами,
Main Take, единичным масштабом, без frozen transforms, динамики и expression-
драйверов на источниках. Для Trajectory требуется статический редактируемый
сплайн; его историческая позиция сверяется с нативным Align на текущем кадре.
Несовпадение более 0.05 см диагностируется вместо незаметного неверного движения.
История начинается с Min Time проекта с нулевой скоростью; до Min Time эффект
выключен. Предел прототипа — 500 секунд истории. Холодный расчёт длинного кадра
может быть дороже повторной оценки; это не обещание постоянного времени на любой сцене.

Проверки P1, P2 и P3 в C4D 2026.2 — PASS. Девять чистых математических тестов —
PASS. Проверены отставание и затухание во всех режимах, наведение после инерции,
произвольная перемотка и subframes, независимость FX от инерции, нулевой bypass,
ключи силы, восстановление всех эффектов после save/load с пустым кэшем.
Fixture: `tests/artifacts/cine_p3_3622cf16466145ed84605aafe12cb31a.c4d`.

Среднее время 40 повторных expression-проходов при изменении Drift Strength:
0.541 мс в маленьком отдельном тестовом документе. Это не FPS viewport,
не замер тяжёлой сцены и не сравнение производительности со старым CamRig.
Визуальная приёмка, ручные Undo/Redo и Redshift motion blur остаются отдельными
проверками. Bake и дополнительные цели не реализованы.

### Единая панель и доступность полей

- Orbit показывает угол, радиус, высоту и центр.
- Trajectory показывает сплайн и Progress.
- Free показывает Free Controller.
- Main содержит режим, общие смещения и статус.
- Look содержит наведение, цель и композицию; Camera — ссылку на нативную оптику.
- Effects объединяет группы Inertia, Shake и Drift.

Все группы видны одновременно, значения и ключи сохраняются. Поля неактивных
режимов пока не блокируются. По разъяснению Maxon, для настоящего серого/недоступного
поля нужен GetDEnabling у собственного плагина; DESC_EDITABLE управляет редактированием
описания, а не доступностью значения. [Ограничение API](https://developers.maxon.net/forum/topic/16124/python-tag-plugin-is-it-possible-to-disable-ghost-the-host-object-s-parameters/1).
Отдельный UI-редактор отменён пользователем и удалён из исходников. Остаётся
одна нативная панель; блокировка полей не реализуется в текущем варианте.
Автоматическое скрытие и внешние UI-обработчики не используются. Cine_UI исключён из исходников, установленная
точка входа отключена (`Cine_UI.pyp.disabled`); перезапуск не требуется.

В .c4d сохраняются стандартные объекты, нативные User Data и два Python Tag
с полным кодом. CamRig/CK_CAM/UI-плагин на машине рендера не нужны. Требуется
совместимая Cinema 4D с исполнением Python Tags и используемый рендерер (Redshift
для RS-камеры). Проверена локальная загрузка с восстановлением эффекта из пустого
кэша; конкретная ферма и пакетный рендер на ней ещё не проверялись.
Нативные группы User Data описаны в [документации Maxon](https://help.maxon.net/c4d/s26/en-us/Content/html/5826.html).

Исходники и проверочный сценарий: [prototypes/cine_camera](../prototypes/cine_camera/README.md).
Не считать статическую компиляцию доказательством работы в C4D.
Не обещать ускорение относительно старого рига без сопоставимого замера.

P1 требует корень верхнего уровня, масштаб 1, отсутствие frozen transforms.
Ключи и ручные трансформации ставятся на корень, пользовательские центры/цели
и опубликованные UD; внутренние управляемые узлы не предназначены для правки.
Внешние цели с выражениями требуют отдельно согласованных приоритетов;
в базовую приёмку входят прямые ключи объектов. Нативный Target может требовать
отдельного управления up-vector при проходе через полюс — это открытая проверка.
Смена режима наведения и ссылок не анимируется. Автофокус и bake пока не реализованы.
Панель использует нативные группы; ограничения P3-эффектов описаны выше.
