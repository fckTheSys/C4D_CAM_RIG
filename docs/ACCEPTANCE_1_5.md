# CamRig 1.5 — отчёт приёмки, 2026-09-08

Статус: рабочая development-реализация основных функций; не полная приёмка исходного плана и не публичный релиз. Автоматическое создание/Show/Hide нативного HUD заблокировано отсутствием Python API. Другой интерфейс без решения владельца не подставлялся.

## Git и исходное состояние

Ветка feature/orbit-controls-targets создана из полного dirty worktree feature/improvements. Baseline-коммит 00f7490 сохраняет исходники, untracked реализацию, ресурсы, документы и проектную конфигурацию; перечень файлов и SHA-256 зафиксированы в docs/baseline-1.4.json исходного репозитория. Последующие изменения разделены на параметрическую схему, runtime, команды/миграцию, UI/диагностику, проверки и документацию.

Слияния/reset/push не выполнялись. История origin/main не объединялась. LICENSE не менялся: его MIT-текст конфликтует с коммерческим текстом старого production-сборщика. Новая отдельная development-сборка не объявляет новые условия и не предназначена для публикации.

## Статические проверки

tools/check_project.py выполняется под bundled Python 3.11.4:

- Явная compile-проверка всех модулей .py и точки входа .pyp (без пропуска расширения .pyp).
- 34 параметра: уникальные постоянные ключи, соответствие template/config defaults, embedded-констант и версии schema.
- Версия плагина и embedded runtime: 1.5.0; schema: 2.
- Чистая математика знаковых оборотов и нечисловых/нефинитных значений.
- В runtime нет импорта camrig, чтения файлов и структурных Insert/Remove.
- Проверка локальных Markdown-ссылок.

Это не заменяет запуск c4d API. Для config-only проверки используется минимальная заглушка цвета Vector, а не имитация сцены.

## MCP smoke и настоящий Cinema 4D

MCP ping подтвердил Cinema 4D 2026.2 (2026200). Python внутри процесса: 3.11.4. Выполнены импорт текущих модулей, создание объектов/ригов, чтение и изменение UD, удаление только временных тестовых элементов и Undo/Redo. Точка входа .pyp импортирована в процессе после очистки старого кеша camrig 1.4; диалог 1.5 открылся через GeDialog.Open. Это не равно проверке загрузки плагина при холодном старте C4D.

Основная серия использовала Redshift камеры, отдельная — standard. Автофокус сверялся с итоговой матрицей FX после одного ExecutePasses, включая Offset/Rotation/Shake/Drift и повторное вычисление одного кадра.

Legacy-фикстура содержит точный исходный runtime baseline 1.4, нет новых UD/schema; локальная поза круга ненулевая, Orbit имеет spline-ключи с тангентами. На кадрах 0/12/30/60 максимум ошибки позиции обеих камер: 6.36e-14 единицы сцены; ориентации: 0 радиан; focal: 0. Допуски 1e-4 / 1e-5 / 1e-4 соблюдены. Старый runtime вычислялся дважды для стабилизации одинаковых priorities, новый — один раз. Это проверка синтетической воспроизводимой legacy-сцены, не всех пользовательских архивных сцен.

## Артефакты и воспроизведение

В исходном репозитории, в игнорируемом tests/artifacts/:

- acceptance.json — результаты последнего прогона;
- legacy-before-upgrade.c4d — состояние перед тестовой миграцией;
- camrig-1.5-acceptance.c4d — итоговая сцена с обычной/Redshift камерами, несколькими ригами и двумя анимированными demo-ригами.

Запуск из C4D main thread: загрузить tests/c4d_acceptance.py через importlib.util.spec_from_file_location и вызвать run(). Скрипт создаёт только свои документы; не запускать во время рендера. Перезаписываются только его собственные файлы в tests/artifacts/.

Сборка: tools/build_production_release.py --development --keep-docs --out-root <новый каталог>. Только исходники; .serena, .cursor, git, логи, кэши, тестовые сцены и локальные настройки исключены. Существующий каталог/ZIP не перезаписываются. Bytecode-production режим в эту приёмку не входит.

## Открытые пункты и ограничения

- Show/Hide Rig HUD и автоматическое создание нативного HUD не реализованы. Maxon подтверждает отсутствие Python-интерфейса: [SDK support](https://developers.maxon.net/forum/topic/14678/python-script-is-add-to-hud-possible-to-add-to-my-python-script). Можно вручную Add to HUD для исходных UD; этот сценарий редактирования/анимации ещё не проверен человеком. Требуется выбор: ручной HUD или отдельная панель.
- Не выполнены визуальная ручная приёмка всех кнопок/ползунков, холодный перезапуск с установленной сборкой и повторное открытие на отдельной установке без CamRig. Автономность кода проверена статически и воспроизведением сохранённых embedded-тегов, но не отдельной машиной.
- Upgrade принимает только известный локальный runtime 1.4; неизвестные/кастомные сцены требуют ручного рассмотрения. Общие транзитивные циклы через другие rigs/XPresso/constraints не анализируются.
- Break — не полноценный bake; анимированный Orbit блокируется консервативно целиком. Пресеты, spherical orbit, arbitrary spline, inertia и gizmo-контролы вне версии.
- Лицензирование и публичное распространение требуют отдельного решения владельца.
