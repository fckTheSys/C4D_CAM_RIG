# Проверка путей Camera Rigs 0.5.2

Дата: 2026-09-15. Реальные вызовы Cinema 4D MCP `exec_python`, C4D 2026.2
(`2026200`), установленный `plugins/Cine_CAM/menu.py`. Новые отсоединённые
документы для каждого случая; пользовательские документы не изменялись.
Ниже сохранена диагностика релиза 0.5.2 до исправления. Результаты исправления
0.5.3 приведены в конце документа; старую матрицу не следует читать как текущие ограничения.

## Объём

73 диагностических прогона: 19 вариантов × Cine без инерции / Cine с
Strength=0.5 / CK_CAM, 11 дополнительных сценариев, 5 повторных проверок
отдельно созданных типов сплайна. Это ограниченная матрица совместимости,
не утверждение о проверке всех возможных C4D генераторов и деформеров.

Основная матрица фиксирует ссылку Align, Status и позицию Motion при Progress
50%. Она подтверждает маршрутизацию ссылки, а не полную корректность камеры.
Дополнительные прогоны сравнивают полные матрицы выходной камеры на кадрах
0, 15.25, 30, 5.5, 15.25, а также сохранение/открытие и Undo/Redo ссылок.

## CK_CAM

Любая принудительная замена справочной UD-ссылки Path оставляет внутренний
Path активным и статус Ready. Проверены Linear, Bezier, B-Spline, Tracer,
Circle, ошибочные объекты, пустая ссылка и трансформированные сплайны.
В пользовательской панели эта ссылка объявлена нередактируемой; MCP-проба
намеренно записывала её программно для проверки фактического источника.

Замена в Align тоже перезаписывается внутренним Path. Изменение точек
внутреннего Bezier работает. Удаление внутреннего Path ломает идентификацию
иерархии. Замкнутый внутренний путь, Linear вместо Bezier или масштаб Path 2
отклоняются с диагностикой. В основной матрице CK_CAM эффекты были выключены,
чтобы изолировать выбор пути; это не новая приёмка Walk на внешнем пути.

## Причины и приоритеты исправления

1. CK_CAM `prepare_data` и стадия Prepare используют `objects[2]` / `obj[2]`.
   Поддержки внешнего пути в текущем runtime нет.
2. Cine Inertia безусловно вызывает `GetTangent` при формировании подписи
   геометрии. У Linear и B-Spline этот вызов вызывает исключение.
3. Cine проверяет тип источника как `SplineObject` и не извлекает результат
   Tracer/другого генератора из его cache.
4. Отказ нового источника не очищает предыдущую ссылку Align. Пустая ссылка
   молча возвращает внутренний путь. Эти случаи надо различать в UI/Status.
5. Оба рига требуют внутренний путь как обязательную роль, даже когда Cine
   уже использует внешний. Удаление «ненужного дефолтного пути» останавливает риг.

Сначала нужны корректный выбор источника, понятная ошибка и поддержка Linear/
B-Spline в инерции. Поддержка живого Tracer требует отдельного решения для
истории изменяющейся геометрии, приоритетов генератора и дробных кадров.

## Исправление 0.5.3 — 2026-09-15

Уточнённый сценарий: Tracer **Connect Objects** служит редактором статического
маршрута. Контроллеры можно двигать при настройке, но не анимировать. Движение
камеры анимируется через Progress. Запекание Tracer не требуется.

- В обоих ригах Path — единственная управляющая ссылка. CK_CAM больше не
  подставляет внутренний сплайн. Пустая/ошибочная ссылка отключает Align с диагностикой.
- Общий `prototypes/path_source.py` встраивается в оба Python Tags при создании.
  Читается актуальный spline cache Tracer и его полная мировая матрица.
- Стадии выполняются в Generators: Prepare 100, Align 110, Cine Inertia 115,
  Target 120, CK Finish 140. Выбор категории использует нативный
  [PriorityData API](https://developers.maxon.net/docs/py/2026_2_0/consts/PRIORITYVALUE.html).
  Same-pass обновление подтверждено отдельно, без повторных ExecutePasses.
- Inertia читает Bezier-касательные только для Bezier; Linear/B-Spline не вызывают
  `tangent index out of range`. Геометрическая сигнатура сбрасывает историю при правках.
- CK_CAM учитывает трансформацию внешнего пути в длине и направлении шагов.
  Linear использует точные длины отрезков вместо адаптивной аппроксимации углов.
  Кеш длины не хранит ссылку на временный C4D spline cache.
- Внутренний путь можно удалить после назначения внешнего. Inspector и Movement
  поддерживают такую структуру. Старые сохранённые риги не мигрируются автоматически.

- 8 базовых: Cine/CK × editable Linear/B-Spline/Bezier/Tracer; подмена ссылки,
