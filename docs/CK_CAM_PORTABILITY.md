# CK_CAM: перенос сцены без установщика рига

Проверено 2026-09-15 в Cinema 4D 2026.2 (`2026200`). CK_CAM записывает
код вычисления внутрь двух обычных Python Tags. Файлы конструктора и меню
нужны для создания рига, но не читаются этим кодом при вычислении сцены.
Код импортирует только `c4d` и стандартные `math`, `bisect`.

## Живая проверка

Тест [portability_acceptance.py](../prototypes/simple_camera/portability_acceptance.py)
создал собственный отсоединённый документ с анимацией маршрута, прыжка,
интенсивности ходьбы, длины шага и частоты shake. Он сохранил сцену и
открыл её заново. В тестовой копии Python Tags используют отдельный словарь
builtins: разрешены только указанные импорты, `open` заблокирован.
Самопроверка подтверждает отказ импорта `camrig` и доступа через `open`.
Глобальные Python hooks и настройки приложения не менялись.

Повторное вычисление на кадрах `149.25, 0, 90, 37.125, 180, 15.5, 120,
130.75, 89.5, 175, 90` совпало с исходными матрицами: максимальная разница
компоненты **4.3021142204224816e-16**, допуск `1e-5`. Оба защищённых тега
выполнялись, runtime diagnostics пусты, нативные связи Align/Target сохранились.
Тест закрыл только созданные им документы.

Локальное доказательство:
`tests/artifacts/ck_portability_879d82f5dfb24e438e68e26cba64dc67.json`.
SHA256 встроенного кода обоих исходных тегов:
`694d1ef9cbdfba1c86b97a26e3eba3a6d10a5377791cecb24f23a651f24e02d7`.

## Что требуется на другом компьютере

- Совместимая Cinema 4D с выполнением Python Tags.
- **Redshift Camera, тип `1057516`**: текущий CK_CAM создаёт именно её,
  без замены на стандартную камеру. Установщик CK_CAM эту зависимость не заменяет.
- Для рендера — соответствующий рендерер, лицензия и обычные зависимости сцены.

Проверка выполнена в том же процессе C4D с уже загруженными плагинами.
Изоляция пространства Python Tags подтверждает отсутствие обращений к файлам
рига и его Python-модулям, но не является системной песочницей или проверкой
чистой установки. Физический другой компьютер, запуск без установленных
CK_CAM/Cine_CAM, рендер-ферма и motion blur пока не проверены.

Следующий приёмочный шаг: открыть обычную сохранённую сцену на отдельной
совместимой установке C4D с Redshift, без CK_CAM/Cine_CAM, проверить эти кадры
и выполнить короткий рендер. Тестовая сцена с защитной обёрткой предназначена
для QA; в пользовательские риги эта обёртка не добавляется.
